# WriterCraft consumer contract

Status: preparation and source mapping, 2026-11-09. This document preserves the complete original Studio Canvas consumer requirements while CraftCanvas develops full native React Flow functional parity. It is not an implementation checklist marked complete, an independent omission review, or native acceptance.

The reusable library baseline is defined separately in [React Flow parity](REACT_FLOW_PARITY.md). The two inventories are cumulative: completing that library inventory does not establish WriterCraft B01–B26 parity, and WriterCraft's four-side card handles do not limit the library's general port model. Allocation of a responsibility to WriterCraft keeps the feature required; it does not remove it from delivery.

## Architecture prerequisites for the production library

These are concrete design inputs for [architecture](architecture.md) and the full [React Flow inventory](REACT_FLOW_PARITY.md), not an independently approved replacement architecture or narrower completion boundary.

### WC-ARCH-01 — Named/dynamic ports with compatible defaults

The current `ConnectorEndpoint` identifies a node and optional side only. Several handles on one side require a separate stable port identity, measured position and source/target/loose eligibility. Dynamic port changes need exact-base validation and a defined dangling/hidden-port policy. Preserve existing Studio side fields and omitted-side bytes; legacy Top fallback is presentation only. Dropping a reconnect back on the original displayed port must not silently turn an omitted side into `Some(Top)`. The same-card distinct-side workflow remains required, and imported equal/omitted-side loops remain renderable.

### WC-ARCH-02 — Gesture lifecycle and native input ownership

Specify ordered start/update/validity/end/cancel events, primary/touch/keyboard identities, ownership and accessibility before freezing public gesture types. Every started interaction needs a terminal outcome, including cancellation and no-op completion. An existing edge remains canonical until a valid guarded change is acknowledged. Escape, focus loss, pointer loss, outside/cancelled drop, base change and host takeover cannot mutate it. Owned release/cancel frames must remain identified after transient state clears so the host cannot reinterpret them as label edits or placement. Embedded editors/media controls win before graph actions; wheel/scroll/pinch ownership needs an explicit contract separate from pointer-button capture.

The baseline view does not explicitly cancel move/resize on `PointerGone` or leaving the viewport. Keyboard capture clears an existing gesture, but its main pointer branch only excludes pointer capture, allowing a new gesture in that frame. These are source-inspected implementation hazards to resolve with focused real-event regressions, not newly verified runtime outcomes. F-47's primary interaction is port/end-point dragging; secondary property dialogs cannot substitute for it.

### WC-ARCH-03 — Transform, measurement and presentation ownership

Keep f64 canonical coordinates and relative-origin conversion. Define node origin, measured size, parent-relative/world transforms and port/body/label coordinates explicitly. Paint, hit testing, clipping and emitted evidence must share the same frame geometry. The baseline processes camera input after painting the current geometry; new port hits must not mix that old presentation with the updated camera. Native widget identity and composition must survive zoom, clipping, movement and persistence acknowledgement without remounting a second text authority.

### WC-ARCH-04 — Controlled state, validation and durable authority

Retain the private-session `ContentIdentity`, immutable `PreparedChange`, host-allocated IDs and one canonical document. Separate observable interaction events from guarded mutation intents. Immediate connection validation needs source/target/port context and actionable reasons; final command preparation must validate again against the exact base. The present `can_connect(node)` plus whole-document validation is useful but insufficient for rich port rules. Before-delete policy must support defer/veto/transform decisions with exact-base revalidation, rather than a notification after deletion. Reconnection keeps the edge ID, exact expected endpoint and unrelated raw fields. WriterCraft checkpoints durably before acknowledgement; library Apply alone never means saved project data. Any convenience API must preserve these guarantees.

### WC-ARCH-05 — Explicit geometry and policy profiles

Current defaults include integral geometry, minimum dimension 40, bounded camera zoom and rounded move/resize deltas. Preserve the Studio compatibility profile while allowing general-library precision, sizing, snapping, constraints and input policy to be configured deliberately. No profile silently lowers imported source capacities or rewrites existing data. Semantic project rules remain in the host dialect; the same policy must govern pointer, keyboard, programmatic and headless commands.

### WC-ARCH-06 — Bounded queries, rendering and extension hooks

Baseline ID indexes, linear topmost bounds hits, body rendering and built-in routes are useful foundations. Full-library queries need consistent world-space intersection/reveal/selection semantics, bounds/cost accounting and a measured indexing/cache strategy. Custom node/edge/port/label rendering must provide corresponding hit/accessibility/ownership geometry. Independent extension callbacks cannot paint a different target than the one receiving input. Layout/export must consume detached bounded data and must not acquire filesystem/network authority from raw strings.

### WC-ARCH-07 — Preservation and evidence across the consumer boundary

Generic library evolution must not replace Studio's schema, original media or history with a lossy graph projection. Preserve existing transfer versions 1–8, editor schemas 1–4, old/custom kinds, source provenance, unknown data and exact references through the application compatibility contract. Every new typed extension needs compatible defaults and semantic round-trip evidence. Keep local text history distinct from durable board history, pending drafts distinct from saved content, and preview state distinct from Apply. Public examples/fixtures are synthetic; private projects remain local/read-only unless separately authorized.

## Downstream acceptance and evidence handoff

WriterCraft retains its existing [UX gate](https://github.com/avacadorun-dev/writer-craft/blob/fb873727027c7e24e91d22a9448dbfe2c791908a/docs/design/UX_GATE.json) and [role journeys](https://github.com/avacadorun-dev/writer-craft/blob/fb873727027c7e24e91d22a9448dbfe2c791908a/docs/design/ROLE_JOURNEYS.md); this file creates no competing approval authority. In particular, PT-LINK-01 must connect board planning, exact document navigation/promotion, scene editing and return to the prior camera/selection; PT-MIG-01 must retain old/custom projects, boards and original assets through import/reopen/portable restore. Layout changes cannot silently reorder or edit manuscript content.

For each implemented consumer slice, record exact engine and application SHAs/locks, hosted checks, platform/build, synthetic fixture, native entry/actions, observed outcomes, independent reviewer findings and accepted limitations. Join B IDs to the relevant OpenSpec and stable journey IDs. Hash the reviewed report. Historical captures apply only to their recorded candidate; a compiler, model test, library demo or output screenshot does not prove a complete native lifecycle.

B01 keeps every committed sub-operation: `create-card`, `edit-inline`, `native-selection`, `native-clipboard`, `native-ime`, `render-gfm`, `reopen-edit`. B26 keeps `local-text-undo-redo`, `board-undo-redo`, `save-reopen`, `pending-save`, `stale-rejection`, `save-failure`, `cancel-preserve`, `recovery-reopen`. Their native-OS flags remain as recorded in `PARITY_SCOPE.json`; other semantic checks do not replace the required OS input observations.

Use the existing checks, focused regression tests for actual defects and concise independent compiled review. Do not create an exhaustive combinatorial matrix. Still exercise the applicable keyboard/IME/clipboard, pan/zoom/clipping, overlapping targets, source policies, failure/stale/cancel/recovery and old/custom-data preservation paths. Split grouped B rows if review reveals an omitted operation; never claim a whole row passed because one imported object renders.

No B01–B26 row is accepted by this mapping. The latest roadmap allows the exact WriterCraft-ready engine checkpoint after CC-12 to unblock integration while CC-13/CC-14 complete the remaining standalone React Flow goal. Every consumer-required primitive must be qualified before that handoff; no B row can be deferred merely by assigning its required engine behavior to CC-13. Complete consumer integration/native acceptance remains separately required afterward. A separate WriterCraft agent may ship a bounded non-Canvas alpha.3 meanwhile. This document grants no publication, issue-closure or release approval.
