## Reachable original behavior

| Area | Source-backed contract |
| --- | --- |
| Resize entry and minimums | `CardResizer` delegates to React Flow `NodeResizer`, visible when board editable and node selected. Minima: ordinary text/document/image/PDF/audio/video/link/nested/external-file cards 180×120; spatial groups and frames 240×160; shape elements 40×40. The wrapper supplies no max-size, aspect, origin, direction or lifecycle override. Refs: `S:canvas-board.tsx:325–343`, call sites `:379/:447/:484/:522/:592/:632/:695/:760/:842/:872/:906`. Board editability is `editable && tablet && activeView === "free"` at `:1142`; tablet threshold is 768px at `:1135/:1184`. |
| Commit/history | React Flow node changes update transient nodes; a `dimensions` change with `resizing === false` calls `commitFlow`. `flowToCanvas` uses measured width/height first, then explicit width/height, then original; rounds x/y/width/height; spreads the original record/extension. One resulting document passes `commitCanvasHistory`, flow resync and host `onChange`. Refs: `S:canvas-board.tsx:2628–2638`, `:1404–1426`; `S:flow-codec.ts:97–169`. This proves a terminal-size commit path, not that Escape/focus-loss cancellation is correct; no explicit resize-cancel handler is supplied by Studio. |
| Durable geometry limits | Server validation requires integer x/y within ±10,000,000 and integer width/height within 40–10,000 (`S:internal/canvas/document.go:151–155`). These are broader than UI per-kind minima. Imported valid small cards must not be silently enlarged by rendering. Wrapper lacks explicit max 10,000, so avoid assuming UI and save limits are already consistent. |
| Images and aspect | Upload stores a media resource reference; initial width is 300 for images, 320 for PDF/audio, 360 for video. Initial image/PDF height is round(width / ratio), where metadata ratio is clamped to 0.35–2.5, fallback 0.78; audio/video heights 130/210. Placement is centered then rounded (`S:canvas-board.tsx:1615–1653`). Image presentation is `size-full object-cover`, not an intrinsic-size canvas (`:469–493`). Rectangle aspect can differ from original media; cover presentation crops to fill. There is no explicit image aspect-lock control or `keepAspectRatio` setting in the source. Resizing changes the card geometry/reference record; it does not request resampling or replace original media bytes. |
| Shape rotation | Arrange → Rotate is enabled when any selected shape exists. Dialog accepts finite degrees, comma decimal normalized to dot, default 15. Operation affects selected `type=group` + `element.kind=shape` only, adds degrees and normalizes to [-180,180). It preserves x/y/width/height. Rendering rotates the SVG shape/label around width/2,height/2, while node rectangle and port components remain outside that SVG transform. Refs: `S:canvas-board.tsx:2160–2176`, `:3270–3281`, `:760–821`; `S:canvas-operations.ts:116–136`; persisted rotation accepts [-360,360] at `S:internal/canvas/document.go:274–280`. There is no source-backed general card/image/stroke/frame rotation control. |
| Origin | Canonical records and operations use axis-aligned top-left x/y with width/height: `canvasToFlow` passes position directly and explicit initial/style dimensions (`S:flow-codec.ts:59–79`); containment uses x+width/y+height (`S:canvas-operations.ts:148–155`). Studio supplies no `nodeOrigin`, parentId or relative transform in this codec. Shape visual rotation center is separate from node position origin. |
| Snapping | React Flow receives 20×20 snap grid, disabled while Alt state is held (`S:canvas-board.tsx:1190–1200`, `:2574–2575`). An additional single-position-change alignment pass considers non-spatial objects/peers, with left/center/right and top/center/bottom candidates within 12 world units; center-center wins before nearest distance, then stable encounter order. Guides extend 24 units beyond bounds (`S:canvas-operations.ts:34–105`; `S:canvas-board.tsx:2592–2627`). Multi-position batches and spatial groups skip this custom guide pass. The callback is not restricted to drag events; dependency behavior must establish whether left/top resize position changes enter it. |
| Group/frame distinction | Spatial groups are `type=group` without an element extension (`S:canvas-operations.ts:398–400`). Group dragging translates fully enclosed records using original group bounds (`:212–230`; `S:canvas-board.tsx:2648–2675`). Frames carry `element.kind=frame`; they are not spatial groups and move independently. Both use the larger resize minima. Their resize path changes rectangle size only; no group-child scaling or persistent parent hierarchy is established. Creation margins differ: groups left32/top56, width+64/height+88; frames left48/top64, width+96/height+112 (`S:canvas-operations.ts:158–209`). |

**Reachability distinction:** the codec contains stroke-point rescaling (x/y independently, two decimal places, pressure retained) in `S:flow-codec.ts:132–159`, but `CanvasStrokeCard` has no `CardResizer` (`S:canvas-board.tsx:713–733`). This is transform support in conversion, not proof of reachable stroke resizing. Shape resizer and image resizer are reachable. No numeric width/height property editor or persistent aspect selector was found in the bounded board source search.

## Host versus generic allocation and current engine gaps

`E:docs/WRITERCRAFT_CONSUMER.md:45` (B04) assigns selectable/resizable geometry and opaque asset references to the engine; original acquisition/storage/decoding, presentation constraints and unavailable-media UI remain host-owned. `:52` (B11) assigns generic multi-object transforms, resize/rotation, hit precedence and cancellation to the engine; source locks/types, sizing policy and contextual controls to the host. `:93` requires deliberate generic profiles while preserving Studio compatibility. Source-required transforms/rotation/groups remain pre-CC12 obligations (`E:docs/REACT_FLOW_PARITY.md:179`); RF-004/006/026/027/061 additionally require measured sizing/origins, hierarchy, controls and generic transform policy beyond original Studio.

Current engine has f64 top-left rectangles; session-wide min/max/integral defaults 40–10,000; guarded SetGeometry separately checks move and resize permissions (`E:crates/craft-canvas-model/src/geometry.rs:23–42`, `document.rs:42–69`, `commands.rs:379–403`). Native resize is one selected node's bottom-right control, independent rounded/clamped width/height, one guarded transaction on release (`E:crates/craft-canvas-egui/src/view.rs:868–883/:940–954/:993–1003`). No aspect policy, other corner/side controls, direction restriction, per-node width/height constraints, multi-selection scaling, configurable node origin/grid/guides or typed rotation/transform-aware body/port hit contract was found. Spatial-group expansion and independent Frame movement exist (`E:crates/craft-canvas-model/src/lib.rs:116–123`, `commands.rs:1022–1063`); persistent parent-relative transforms remain a separate gap. Camera relative-origin precision is not node-origin support.

## Decisions/evidence to settle before sizing API design

1. **Exact dependency defaults are not fully inspected.** The original lock pins React Flow 12.11.2 / system 0.0.79 (`S:bun.lock:850–852`), but its installed package files are absent in this checkout. The available separate RF research tree is newer and cannot prove original default handles, side/corner anchor behavior, Shift/aspect handling, resize snapping or cancellation. Inspect that exact archived dependency when available; do not infer that omitted aspect prop means a verified modifier gesture. No network/install was attempted.
2. **Keep three concepts separate:** intrinsic media dimensions, mutable displayed card rectangle, and optional generic aspect constraint. Original metadata-based initial sizing and object-cover do not authorize an always-locked image aspect. Generic aspect support is a broader RF requirement; host chooses compatible defaults.
3. **Resolve lock consistency rather than preserve a likely bug.** `S:flow-codec.ts:69` marks locked nodes non-draggable, but CardResizer does not inspect `locked` and `rotateCanvasSelection` does not filter it. The source therefore does not establish consistent locked resize/rotation refusal. The documented host/dialect policy must be explicit and apply to native and headless commands.
4. **Define rotation space explicitly.** Original shape-only SVG rotation does not rotate node bounds/ports or grouped children. A general transform API must preserve this legacy interpretation while separately specifying pivot, transformed hit geometry, connectors and parent semantics; do not silently reinterpret existing `element.rotation` as whole-node rotation.
5. **Define resize/rounding/snap precedence and imports.** Preserve valid existing small/fractional unknown data without render-time normalization; Studio authored geometry is integral, UI type minima differ from storage minima, and its custom single-position guide pass may also see resize updates. Native policy must state when constraints/rounding/snap apply and what a no-op/cancel preserves. Per-kind values and source stroke-point updates belong to the host dialect; reusable constraint/gesture mathematics belongs in CraftCanvas.

Public-safe summary: original Studio offers selected-card resize with type-dependent minima, metadata-informed initial media sizes, cropped image display, shape-only center rotation, 20-unit grid plus alignment guides, and distinct spatial groups versus frames. It does not establish a universal aspect lock, general node rotation or persistent nested-parent geometry. Current CraftCanvas is only a partial sizing foundation.
