# Embedded draft and acknowledgement

One editor captures an exact source/session/node and an independent process-local native widget identity. Its text remains noncanonical. The widget renders inside the reserved board body at its effective zoom, using a clipped local scroll region. Native selection, paste, local Undo and composition retain input ownership; board gestures/shortcuts are suppressed while a child owns input. OS blur preserves the draft. Only deliberate same-window pointer blur or Cmd/Ctrl-Enter requests Done; Escape requests local cancellation outside IME.

Submit captures an immutable copy of the exact current text but does not freeze later typing. Acknowledge verifies the same canonical session and the exact submitted node source after host durable-save plus Apply, then advances expected/base without replacing later text or changing the widget ID. Failed/unstarted submissions never become acknowledgements. The host must retain any pending candidate and later draft on failure, and use exact-base checkpoints before claiming autosave. Local text Undo remains distinct from canonical board Undo after editing ends.

## Keyboard entry and discoverability

Enter offers the same bounded EditText intent as pointer activation. Its eligibility is exact: one current text node and no selected edges; the current keyboard focus must be the Canvas response or that selected node, rechecked after child body rendering. Captured child input, IME batches, host modal/disabled state and other native controls keep their events. A non-repeating, unmodified Enter is removed by an exact event match; egui's logical shortcut matcher is unsuitable because it deliberately ignores extra Shift/Alt modifiers.

The current generic dialect exposes geometric permissions rather than a separate text-edit permission. This entry point conservatively requires `node_policy(node).movable`, matching the existing WriterCraft host lock guard. The host remains authoritative and may refuse the guarded intent. This does not authorize editing locked cards or introduce a new permission model. The localizable `CanvasViewLabels::edit_text_hint` identifies both entry methods on eligible card hovers. After an intent, the existing armed activation and pre-input grant preserve AccessKit validity and native input; no focus request is added to the post-paint intent path.
